# RMM UI/UX Polish v1

Device details now combine endpoint identity/status, linked asset tag, Windows/build, user, serial and last-seen information in one summary. The old duplicated Overview/Management cards and unfinished-capability placeholders were removed. No management capabilities were added.

Hardware uses responsive CPU, installed-memory, individual DIMM and physical-disk cards. Every reported module includes manufacturer, capacity, part, configured/rated speed, bank and locator. Display cleanup collapses harmless whitespace without changing stored RAM values. Reported speed retains its existing MHz label; no DDR generation is inferred. No storage media type is guessed. Physical disks are explicitly distinguished from the Windows logical system volume. BIOS and architecture are grouped with a secondary selectable UUID.

The only new collection field is physical_disks[].manufacturer, taken from the existing Win32_DiskDrive query and bounded to 200 characters. It uses existing JSONB storage with no migration. Missing manufacturer on old array items stays absent; null stays null; omitting physical_disks preserves the previous snapshot. No additional CIM query, scheduling change, lifecycle change or remote action is introduced.

Device Health now has compact accessible meters alongside numerical values and existing warnings. Thresholds, sample coverage, current/stale/unknown semantics and online/offline behavior are unchanged. The header labels hardware's last check-in as context, with an explicit note that no dedicated hardware scan timestamp exists. It does not infer a successful hardware scan from heartbeat freshness.

Windows Update entries use compact cards with textual classification chips (reported categories/classification IDs), KBs, severity, downloaded/reboot state, and expandable identity. Unknown classifications stay unclassified. Existing scan action and job-ID feedback remain unchanged. Software keeps its search and registry-view filter, adds an inventory-age summary and improves table typography/details. Recent Jobs is an activity list with friendly names, distinct lifecycle labels, request/completion timestamps, elapsed duration and secondary IDs.

`server/public/rmmUI.js` centralizes byte units (GiB/TiB), human durations, relative age, timestamps, percentages, unknown values, whitespace cleanup and job/classification labels. Existing theme tokens style all cards; responsive grids avoid horizontal scrolling in hardware/health. Software can scroll when needed. Meter values remain visible as text and have accessible progressbar attributes; warnings/classification do not depend on color alone.

Regression coverage renders component element trees from the actual JSX for CPU/DIMMs/disks, health meters, light/dark tokens, identity summary, update cards and software rows, plus shared formatting/job labels and existing action-feedback tests. Disk manufacturer has route validation/JSONB/omission tests and mock PowerShell CIM/serialization coverage.

Live browser validation remains necessary for desktop/narrow-screen layout, actual light/dark contrast, focus/keyboard interaction and visual density. Native Windows verification of the new manufacturer field remains necessary; Linux PowerShell tests use mocked CIM.

## Hardware data-quality follow-up

DIMM manufacturer collection remains unchanged: `Win32_PhysicalMemory.Manufacturer` is a firmware-supplied SMBIOS string ([Microsoft property documentation](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-physicalmemory)). The UI maps only exact four-digit identifiers (case-insensitive, optional `0x`): 802C/2C00 → Micron, 80AD/AD00 → SK hynix, 80CE/CE00 → Samsung, and 8551/5105 → Qimonda. These encodings are documented in [Cisco's memory inventory reference](https://www.cisco.com/c/en/us/td/docs/unified_computing/ucs/c/sw/gui/config/guide/6_0/b_cisco_ucs_c-series_gui_configuration_guide_6-0/m_gui_viewing_server_properties.pdf). Unknown, extended and malformed strings remain as reported; non-string/empty values display Unknown. The raw manufacturer remains stored and available in the DIMM card tooltip. No part-number inference, extra CIM query or PowerShell change is involved.

The Windows System Volume card reuses sample-covered Device Health drive, utilization, total and free values; used space is total minus free when both are available and consistent. Stale snapshots display values explicitly as **Last reported**, with timestamp and stale status. Missing/invalid/future snapshots remain Unknown, and fields omitted from sample coverage never appear as current or last-reported samples. Physical disks stay separate; their manufacturer still comes only from CIM, never model parsing. Compact DIMM/disk metadata omits unavailable entries instead of repeating Unknown separators. Individual DIMM cards are retained.

Regression tests cover known/unknown/malformed manufacturer values, raw-ID visibility, missing physical-disk manufacturers, current/stale/missing/partial system-volume snapshots and derived used space. This follow-up changes presentation only; no collection, schema, cadence, health thresholds, polling or job behavior changes. Windows PowerShell 5.1 endpoint validation and live browser visual validation remain separate from Linux mock/component tests.
